## 1. 代码排版长什么样（先认路）

所有脚本在 `Assets/MoMing/Scripts/`，按功能分文件夹：

```
Scripts/
├── Core/          — 全局系统
│   ├── GameManager.cs      焦虑值、变暗/聚光、关卡重置、通关切场景（单例）
│   ├── PlayerManager.cs    Tab 切角色、Q 联动、距离判定（单例）
│   ├── CameraFollow.cs     俯视角摄像机：跟随/联动/提示镜头  ← 摄像头核心
│   └── SceneLoader.cs      UI 按钮切场景
├── Player/        — PlayerController：单个角色的移动/跳跃/拾取/交互
├── Enemy/         — MonsterPatrol：怪物巡逻 + 视野 + 追击
├── Environment/   — FootprintMarker（脚印）/ HintTrigger（提示触发区）
├── Puzzle/        — 机关：开关、门、踏板、箱子、拾取物、存档点…
├── UI/            — HUD、设置面板
└── Audio/         — MusicTable / MusicManager（音乐系统）
```

**几条能帮你快速看懂的规律：**

- **单例（Singleton）**：`GameManager`、`PlayerManager`、`MusicManager` 都有 `public static Instance`。任何脚本用 `GameManager.Instance.xxx` 就能拿到，不用手动拖引用。看到 `Instance` = 全局唯一管理器。
- **管理器 vs 控制器**：`XxxManager` 管一类全局事务；`XxxController` 挂在单个物体上管它自己。
- **事件回调**：`PlayerManager` 里有 `OnTogetherChanged`、`OnActiveCharacterChanged` 这类 `System.Action`，别的脚本可订阅，在状态变化时被通知。
- **`[Header]` / `[Tooltip]`**：字段上的标签，会在 Inspector 里显示成分组标题和悬停提示。调参基本都在 Inspector，不改代码。
- **`[SerializeField] private`**：私有但仍能在 Inspector 赋值。

## 2. 摄像头是怎么跑起来的（数据流）

```
玩家按 Tab（切人/狗）
  → PlayerManager.HandleSwitch() 改 activePlayer
  → 调 CameraFollow.SetTarget(新角色)   ← 视角切过去，并触发一次平滑转场

玩家走进 HintTrigger 触发区
  → HintTrigger.OnTriggerEnter()
  → 调 CameraFollow.PlayHint(要指的机关) ← 镜头飞过去停一下再飞回

CameraFollow 每帧 LateUpdate()
  → 算焦点（当前角色 / 双人中点 / 提示目标）
  → SmoothDamp 平滑移动摄像机 + 处理遮挡隐藏
```

现在 `CameraFollow` 支持：跟随当前角色、联动跟双人中点、鼠标转视角、切角色/联动的平滑转场、提示镜头 `PlayHint()`、提示期间冻结镜头旋转 + 强制只能走路、遮挡物自动隐藏。

## 3. 关于 Cinemachine：建议**不用**

你之前问“能不能用 Cinemachine”。建议**不用**，继续用现在这套手写 `CameraFollow`：

1. 你要的「提示镜头 + 双角色切换」已经用几十行协程实现了，功能齐了，再上 Cinemachine 是重复造轮子。
2. **少一个依赖更省心**：手写这套不依赖任何包，工程更轻，协作时不用担心谁没装/装错版本。
3. **学习成本**：Virtual Camera / Brain / Blend 概念对新手是额外负担，jam 时间宝贵。

将来若要大量电影级运镜，再考虑装 Cinemachine（2022.3 对应 CM 2.x）。现在不用。

---

## 4. 设计说明：为什么这样做

- **提示期间冻结镜头旋转**：角色移动方向是相对镜头 yaw 计算的。若提示时镜头飞走、yaw 变了，玩家一按 W 方向就乱。所以提示期间冻结鼠标转向（yaw 不变），镜头只平移去“指”目标，玩家仍能稳定走路——正好对应「可以走，但只能走路」。
- **只能走路**：`PlayerManager.IsHintPlaying` 为真时，`PlayerController` 屏蔽 Shift 疾跑。
- **不叠加**：正在播放提示时再次触发会被忽略，避免镜头打架。

## 5. 代码 review 小提醒

- 遮挡检测用 `Physics.RaycastAll` + 每帧 new 数组，物体多时可换 `RaycastNonAlloc` 减少 GC。jam 阶段不必。
- 提示镜头目前“正在播放时再次触发会被忽略”。若想“新提示打断旧提示”，可在 `PlayHint` 里先 `StopHint()` 再启动。按需要改，不是 bug。

## 6. Unity 2022.3 兼容性（重要）

全组统一 Unity 2022.3。以下是 2022.3 的正确写法，别改成更高版本才有的 API，否则会编译报错：

| 不要改成 | 保留用 | 说明 |
|----------|--------|------|
| `async / await` / `Awaitable` | 协程 `IEnumerator` + `StartCoroutine` | Awaitable 是更高版本才有的 API |
| `rb.linearVelocity` | `rb.velocity` | `linearVelocity` 是更高版本的新名字，2022.3 没有 |
| `FindFirstObjectByType` | `FindObjectOfType` | 2022.3 用 `FindObjectOfType` |
| 新输入系统 `InputSystem` | 旧 `Input.GetKey / GetAxis` | 全项目用旧 Input Manager，别混用 |

在 2022.3 里 `FindObjectOfType` / `rb.velocity` 都是**当前正常 API，不会有过时警告**，放心用。
