# 项目规范

## 1. MoMing 文件夹规则

所有 AI 创建的脚本、场景、资产统一放入 `Assets/MoMing/` 目录下，按功能分类存放。

> **禁止**在 `Assets/MoMing/` 之外创建 AI 生成的脚本/场景/资产。

### 1.1 初始目录结构

```
Assets/MoMing/
├── Docs/             — 开发文档（.md）
├── Scripts/          — C# 脚本
├── Scenes/           — 场景文件（.unity）
├── Prefabs/          — 预制体（.prefab）
├── Materials/        — 材质（.mat）
├── Textures/         — 贴图（.png/.jpg）
├── Audio/            — 音频（.wav/.mp3）
├── Animations/       — 动画（.anim/.controller）
└── UI/               — UI 资产（UXML/USS/Sprite）
```

> **不创建 Models 文件夹。** 本项目不制作/导入外部 3D 模型，全部使用 Unity Primitive 搭建。

## 2. Unity Primitive 约束（原型阶段）

> **当前为原型开发阶段，不生成/导入任何 3D 模型。** 所有场景物件、角色、道具均使用 Unity 内置 Primitive 搭建。后续替换正式模型时参考下表逐个替换。

| Primitive | 典型用途 |
|-----------|---------|
| Cube | 墙壁、箱子、平台、角色身体、门 |
| Sphere | 球体道具、机关按钮 |
| Capsule | 人形角色碰撞体 |
| Cylinder | 柱子、管道、圆形道具 |
| Plane | 地板、天花板 |
| Quad | 平面装饰、UI 背景 |

## 4. 音频规范

> **原型阶段不导入任何音频文件。** 脚本中预留音频调用接口（`AudioSource` + `AudioClip` 字段），但不实际赋值，仅在下表中记录所需音频清单，后续由用户逐个添加。

### 4.1 脚本音频调用约定

```csharp
// 示例：脚本中预留音频字段，不实际赋值
[SerializeField] private AudioClip footstepClip;   // 暂为 null，不播放
[SerializeField] private AudioClip doorOpenClip;   // 暂为 null，不播放

private void PlayAudio(AudioClip clip)
{
    if (clip != null)
        audioSource.PlayOneShot(clip);
    // clip 为 null 时静默跳过，不报错
}
```

- 所有音频播放逻辑统一走 `PlayAudio()` 包装方法，`clip == null` 时静默跳过
- 音频字段统一标记 `[SerializeField] private`，通过 Inspector 后续赋值
- 不在代码中硬编码加载音频路径

## 5. 命名规范

### 5.1 脚本命名

- 使用 **PascalCase**
- 脚本文件名与类名一致
- 按功能模块加前缀：

| 前缀 | 模块 | 示例 |
|------|------|------|
| `Player` | 玩家角色 | `PlayerController`, `PlayerAbility` |
| `Level` | 关卡系统 | `LevelManager`, `RoomController` |
| `Puzzle` | 解谜机关 | `PuzzleSwitch`, `PuzzlePressurePlate` |
| `Monster` | 怪物 | `MonsterPatrol`, `MonsterSensor` |
| `Anxiety` | 焦虑系统 | `AnxietyManager`, `AnxietyEffect` |
| `UI` | 界面 | `UIManager`, `UIAnxietyBar` |
| `Camera` | 摄像机 | `CameraFollow`, `CameraTrigger` |

### 5.2 场景命名

- 关卡场景：`Level_XX_名称.unity`（如 `Level_01_TreatmentWard.unity`）
- 测试场景：`Test_名称.unity`

### 5.3 预制体命名

- 使用 **PascalCase**，按类型分类存放
- 示例：`Door.prefab`, `PressurePlate.prefab`, `Monster.prefab`

### 5.3.1 预制体分类

| 文件夹 | 内容 | 预制体 |
|--------|------|--------|
| `Prefabs/` (根) | 一体化系统预制体 | `PlayerSystem.prefab`（角色+摄像机+UI+管理器，拖入即用） |
| `Prefabs/Players/` | 单独玩家角色 | `Human.prefab`, `Dog.prefab` |
| `Prefabs/Enemies/` | 敌人 | `Monster.prefab` |
| `Prefabs/Items/` | 道具 | `PushableBox.prefab`, `PickupItem.prefab` |
| `Prefabs/Mechanics/` | 机关/交互物件 | `PuzzleSwitch.prefab`, `Gate.prefab`, `PressurePlate.prefab`, `HoldSwitch.prefab`, `FootprintMarker.prefab`, `LevelExit.prefab` |

> **注意**：`linkedGate`（开关→门引用）和 `waypoints`（怪物巡逻点）为场景级引用，放入场景后需在 Inspector 中重新赋值。材质引用（`Mat_Switch`/`Mat_SwitchActive`）和自引用（`indicatorRenderer`）已保留在预制体中。`PlayerSystem.prefab` 内部所有引用（GameManager→角色/UI、PlayerManager→角色）已预连，拖入场景无需手动赋值。
